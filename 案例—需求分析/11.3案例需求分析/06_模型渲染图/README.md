## 重现

本地采用Java 21、Graphviz 2.42.4、PlantUML 1.2026.9；中文字体为Noto Sans CJK SC。固定jar从Maven Central的net/sourceforge/plantuml/plantuml/1.2026.9下载，并与仓库发布的SHA256核对：

`96ace11f947a04a4320a413a0a2c6bad8b87daaac1869fe51e82622d812fe13c`

从成果根目录执行（需要Pillow；渲染无需上传模型到远程网站）：

```bash
python3 06_模型渲染图/生成模型渲染图.py --jar /path/to/plantuml-1.2026.9.jar
python3 06_模型渲染图/校验渲染图.py
```

“渲染与模型对应清单.json”记录当前SysML、puml、png、svg的SHA256、图尺寸、需求/阶段/角色/接口身份。模型改动后应重新渲染并更新清单，不能继续使用旧图冒充新模型结果。

## 阅读边界

- RD包含3个主需求和20个原子需求短ID；连线表示原嵌套包含关系，不新建deriveReqt/satisfy。
- ACT按原阶段＋doc展开，终点表示一次评估片段结束，不表示停止持续保护/温控。过温保护状态与恢复条件保留；未知阈值不补造。后风窗请求不套用前风窗控制。
- UC保留3个用例、驾驶员和IVI参与者，以及原objective require追溯，无新增include/extend。
- BDD含目标加6个外部角色、6种端口类型和8条接口连接；上下文容器不是第8个外部参与者。原技术信号名是接口标识，不能解读为新增内部硬件；抽象效果连线不代表直接物理换热通路。

## 按用户参考图调整后的样式

本次只更新另外7组图的puml/png/svg，综合用例图三个文件与1ab1853逐字节一致。需求图改为中心需求定义与周边需求卡片；活动图改为带«action»标记的白底圆角卡片和虚线条件连接；BDD改为中心系统、周围角色、方形端口及折线连接。保留原编号、条件和8条BDD接口。未添加参考图中的冰箱、空气质量、远控等业务。

为精确控制参考样式，7份puml采用PlantUML支持的`@startdot`语法，可直接交给PlantUML渲染；用例图保留原`@startuml`文件。BDD的方形端口和折线拐点是绘图元素，不是新增参与者；连接端点含义和方向仍由原输入/输出端口及接口定义确定，按参考图使用无箭头接口线。

需求图简化了卡片正文，完整doc仍保存在[需求条目明细](需求条目明细.md)及SysML；BDD技术接口和全部特征见[外部接口明细](外部接口明细.md)。本次未修改指标表、JSON或SysML业务内容。
