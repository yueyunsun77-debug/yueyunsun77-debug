# Transformer：输入、输出与汇报前自查

适用论文：Vaswani et al., *Attention Is All You Need*, NIPS 2017。对应你当前的《15页白底图解精修版》PPT。

统一依据：[会议版论文 PDF](https://proceedings.neurips.cc/paper_files/paper/2017/file/3f5ee243547dee91fbd053c1c4a845aa-Paper.pdf)。主要定位：§3、§5、§6、Table 1—3。

## 一、老师问“这个技术输入和输出是什么”，先这样回答

> 这篇论文主要研究机器翻译。推理时，模型接收源语言序列，以及已经生成的目标语言前缀，计算下一目标词元在词表上的概率分布。解码程序逐步选择词元并继续生成，最后得到目标语言译文。训练时，输入包含源序列和右移后的真实目标序列，未右移的目标序列用于提供监督标签。

接着补一句，避免把三个层次混在一起：

> 因此，应用层看到的是“原文输入、译文输出”；神经网络一次前向计算得到的是“词表上的分数或概率”；模型内部注意力层输出的是“上下文特征向量”。

## 二、训练与推理的输入、输出分别是什么

| 场景 | 模型输入 | 模型前向结果 | 额外发生的事情 |
|---|---|---|---|
| 训练 | 源序列；右移真实目标序列；必要的掩码 | 各目标位置对应的词表 logits／概率分布 | 用真实下一词标签计算损失，反向传播更新参数 |
| 推理的第 1 步 | 完整源序列；起始标记 | 第一个目标词元的概率分布 | 解码程序选出词元 |
| 推理的后续步骤 | 完整源序列；已生成目标前缀 | 下一个目标词元的概率分布 | 把新词元接到前缀，继续计算 |
| 应用最终结果 | 原始源语言文本 | 生成的目标词元序列，经反分词得到译文 | 遇到终止条件后停止 |

**注意：**训练时的标签参与损失计算，不会作为“待预测位置的正确答案”直接喂给该位置。右移与因果掩码共同保证这一点。起止符号的具体名称、词表 ID 和实现细节可以不同，不能把示意符号当成论文规定的固定名称。

## 三、从原始文本到网络张量

```text
原始源句
   ↓ 分词／子词切分、查词表
源词元 ID 序列
   ↓ Embedding，并加入位置编码
源序列向量
   ↓ 编码器
源句上下文表示 Z
                         已知目标前缀／右移真实目标
                                      ↓ 嵌入 + 位置编码
                      解码器：掩码自注意力 → 交叉注意力 → FFN
                                      ↓
                         目标位置的隐藏表示 H
                                      ↓ Linear
                             词表 logits
                                      ↓ Softmax
                        下一词元的条件概率分布
                                      ↓ 解码程序
                           目标词元序列／译文
```

原文英德任务采用子词编码，不应把模型处理单位一概称为“完整单词”。汇报时可以先说“词”，随后说明严格来说是“词元或子词”。

## 四、用一个具体句子理解“右移”

以下是便于理解的按词示意，**不是原文的真实分词结果、固定词表或实测译文**。

- 源句：`I like books .`
- 目标句：`Ich mag Bücher .`
- 示意起止标记：`<BOS>`、`<EOS>`。

训练时：

```text
源序列：          I       like     books      .

解码器输入：   <BOS>      Ich       mag     Bücher      .
监督标签：       Ich      mag     Bücher      .      <EOS>
```

| 预测位置 | 解码器该位置及之前可见的输入 | 要预测的标签 |
|---|---|---|
| 1 | `<BOS>` | `Ich` |
| 2 | `<BOS> Ich` | `mag` |
| 3 | `<BOS> Ich mag` | `Bücher` |
| 4 | `<BOS> Ich mag Bücher` | `.` |
| 5 | `<BOS> Ich mag Bücher .` | `<EOS>` |

训练中，这些右移输入都已知，所以可以在一个前向过程中并行计算多个位置。推理中，后面的词还没有生成，必须逐步扩展前缀。表格展示的是每个位置的可见范围，不表示训练一定逐行执行。

### 为什么下三角掩码允许看对角线，却没有泄漏答案

预测目标位置 2 的 `mag` 时，解码器输入位置 2 放的是 `Ich`。对角线看见的是右移后已经知道的前一个词，而不是待预测的 `mag`。

## 五、各层技术分别接收什么、输出什么

| 层次 | 输入 | 输出 | 你应当如何解释 |
|---|---|---|---|
| Embedding | 离散词元 ID | 连续向量 | 把符号变成可学习表示 |
| 位置编码相加 | 词向量、同维位置向量 | 含位置线索的向量 | 补充序列顺序 |
| 编码器 | 源序列向量和源 padding 掩码 | 每个源位置的上下文表示 Z | 尚不是译文或目标词概率 |
| 编码器自注意力 | 由源表示投影出的 Q、K、V | 各源位置更新后的特征 | 在源句内部交换信息 |
| 解码器掩码自注意力 | 由右移目标表示投影出的 Q、K、V，加因果掩码 | 各目标位置可用的前缀表示 | 避免访问未来目标 |
| 交叉注意力 | 解码器的 Q；编码器提供的 K、V | 各目标位置融合源句后的特征 | 用目标上下文查询源句信息 |
| 单个注意力头 | Q、K、V，以及适用的掩码 | 与查询位置对应的加权特征 | 注意力权重是中间结果 |
| 输出 Linear | 解码器隐藏表示 H | 目标词表大小维度的 logits | 每个候选词元一个未归一化分数 |
| Softmax | logits | 下一词元的概率分布 | 同一位置上对词表归一化 |
| 解码程序 | 词概率、已有前缀、停止条件 | 完整目标序列 | 可以使用束搜索等策略 |

## 六、常被追问的张量维度

记 batch 大小为 B，源长度为 n，目标长度为 m，目标词表大小为 Vt。以下采用 base：模型维度 512，8 个头，每头键／值维度 64。

| 对象 | 形状 |
|---|---|
| 源词元 ID | `[B, n]` |
| 右移目标 ID、目标标签 | 均为 `[B, m]`，但元素位置不同 |
| 源嵌入、编码器输出 | `[B, n, 512]` |
| 目标嵌入、解码器隐藏表示 | `[B, m, 512]` |
| 编码器单头 Q、K、V | 均为 `[B, n, 64]` |
| 编码器所有头的注意力权重 | `[B, 8, n, n]` |
| 交叉注意力 Q | `[B, 8, m, 64]` |
| 交叉注意力 K、V | 均为 `[B, 8, n, 64]` |
| 交叉注意力权重 | `[B, 8, m, n]` |
| 输出 logits／概率 | `[B, m, Vt]` |

实现可能把 batch 与 head 维度临时合并，或先使用其他维度顺序；上述表格用于解释逻辑形状，不要求所有库的存储布局完全相同。

最一般的单头公式为：

```text
Q: [Lq, dk]
K: [Lk, dk]
V: [Lk, dv]

QKᵀ: [Lq, Lk]
A = softmax(QKᵀ / √dk): [Lq, Lk]
AV: [Lq, dv]
```

关键判断：**输出有多少个位置，由查询 Q 的长度决定；每个位置输出多少维，由 V 的值维度决定。**

| 容易说错 | 更准确的说法 |
|---|---|
| 本文首次发明注意力 | 本文提出以注意力主导序列交互的 Transformer 架构 |
