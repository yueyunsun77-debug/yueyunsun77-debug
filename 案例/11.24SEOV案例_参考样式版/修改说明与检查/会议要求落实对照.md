# 会议要求与优化落实

| 要求 | 本版落实 |
|---|---|
| 功能V+O、主语可省略 | 73条活动/组合/兼容记录显式s/v/o/e，保留原ID，子功能有来源父节点 |
| 需求O+E与功能视角区分 | 三条父需求保留requirement_expression；条款性质通过type/category分开管理 |
| 输入输出概念化 | 为概念端口增加唯一ID、类型引用及请求/实际/目标角色；未知字段和单位不补造 |
| 父子分解及出处路径 | 14个原父活动、3个组合功能及11个新增子功能保留层级路径与ZIP成员来源 |
| 避免幻觉与错误前置条件 | required_capability=null；原生行为模型显式表达使能AND、温度恢复、SOC缺口、场景三OR |
| 时序、并行、反馈 | 六个行为模型199条转移，与转移JSON/Excel和SVG使用同一数据源 |
| 按案例规范动作命名 | 功能、行为节点、目录、表格和JSON追溯一致；消息协议未擅改 |
| 结合扩充清单 | 201项原槽位保留并逐条筛选；参考采用与正式需求分离 |
| 源理工具验证 | 提供导入包及验收步骤；缺少实际工具接入，状态明确为未导入 |

逐字稿仅含会议收尾，不作为整份纪要逐句证明。会议材料中的待办是分析依据，不授权对外联系参会人员。
